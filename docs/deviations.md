# Deviations from upstream

`cordis-lua` ports `cordiverse/cordis` at the commit recorded in [`UPSTREAM`](../UPSTREAM). This document records language-level deviations required by Lua, fixes for confirmed upstream defects, host-environment differences, optional host and lifecycle extensions, and performance optimizations (including minor identity differences where noted). Deliberate design divergences from other ports (such as `cordis-rs`) are not adopted.

## Language-level deviations

| Topic | Upstream | Lua | Why |
|---|---|---|---|
| Promises and microtasks | Promise, `async` / `await`, microtasks | `Future` on a host-injected `spawn` / `latch`; `then` is spelled `next`; `Context.new` takes `{ host = ... }`. Reactions run on a per-host job queue drained by a host task. Causal order is kept; exact microtask interleaving is not guaranteed except where upstream relies on it: a fiber's (re)load and each teardown disposer start after one job hop (`await Promise.resolve()`). `await` on a settled Future returns at once; `cordis.tick(host)` stands for `await Promise.resolve()`. | Lua has no event loop; coroutines must be driven by the embedder |
| Synchronous prefixes and `cordis.async` | `async function` runs synchronously up to its first `await` | The synchronous prefix of every library `async` method runs synchronously. A user callback built with `cordis.async` has no synchronous prefix: a deferred host starts it after the call returns (and where the host's blocking calls cannot resume from a library-resumed coroutine, no host primitive can provide one). Put work that must run before the first `await` in a plain function before returning a `cordis.async` Future. | Deferring executors cannot run a synchronous prefix inside a spawned task |
| Blocking in the job queue and host modes | Microtasks never block natively | Without `capture`, components, disposers, and listeners may run inside a job-queue drainer. Blocking via `cordis.await` / `future:await()` or `cordis.tick` hands the queue to a new drainer; other blocking (such as `host.sleep`) delays later jobs. Use `cordis.async` for long work, or a host with `capture` (where queued components, queued disposers, Future reactions, and `parallel` listeners run in spawned tasks; synchronous `emit`/`bail`/`waterfall`/`serial` listeners still run on the calling task). A host whose `spawn` always defers has only deferred mode; the reference host's eager mode covers hosts that start tasks immediately. | Coroutines block cooperatively rather than yielding microtasks |
| Method receivers | implicit `this`: `ctx.on(...)`, bound mixins, `Reflect.apply(cb, thisArg, args)` | colon calls everywhere; mixin and traced-method wrappers drop the passed receiver and substitute the right one; listeners of a dispatch with `thisArg` receive `(thisArg, ...)` (affects `internal/service`, `internal/update`, `internal/listener`); callable services are dot-called; a method called through a traceable proxy returns every value the implementation returns, the first traced like upstream's single result, and a method that is a Lua function is read as a function (upstream's `Proxy` of a function is `typeof === "function"`; a callable table stays a proxy) (`trace.lua` `createShadowMethod`) | Lua has no `this`; Lua functions return several values |
| Proxies | `Proxy` (context, traceable services), the `in` operator | tables with `__index` / `__newindex` / `__call`; context state lives in hidden storage so every access passes the metamethods; `name in ctx` is `Context.has(ctx, name)`; `rawget` / `rawset` / `next` bypass the proxy; callable services have `type()` `"table"` | metatables are Lua's only interception mechanism |
| Classes | `class`, `new`, `isConstructor`, decorators, `Symbol.hasInstance`, `Function.prototype.name` | `cordis.class(name, parent)`; `new Class(...)` is `require("cordis.class").construct(Class, ...)`, which the library uses to construct components (`Class.new` is a convenience field, so a class may define a method named `new` without breaking construction); components are functions / callable tables, tables with `apply`, or class tables; `Inject(Class, name, config)` and `Inject.method(Class, method, deps)`; `Service.is(x)`. Lua functions have no name, so a function component's runtime is unnamed (`fiber.name` falls back to the parent's); a table component's `name` field and a class's name are used as upstream | no classes or decorators; a function cannot be told apart from a constructor |
| Generators | generator and async generator effects | `cordis.iter(fn)` / `cordis.asyncIter(fn)` with an explicit `yield(dispose)` callback; the async form runs in a host task and checks the epoch after every `yield` | the library may not drive coroutines; a plain function cannot be told apart from a generator |
| Symbols | `Symbol`, `Symbol.for` | `cordis.symbol(desc)`, `cordis.symbolFor(key)` (unique per Lua state and library copy) | no symbol type |
| Null values | `null` and `undefined` | `nil` only; `cordis.null` where upstream stores `null` (inject configs); `isBailed(v)` is `v ~= nil and v ~= false and v ~= cordis.null`; `then` / `prototype` are not reserved property names | Lua tables cannot hold nil, there are no thenables |
| Ordering | insertion-ordered objects, `Map`, `Set` | `cordis.ordered` Map / Set and ordered proto objects. A plain Lua table used as a dict (`inject = { a = ..., b = ... }`, `mixin(src, { sourceKey = "alias" })`) has no order; it is read in sorted key order. Sequences and proto objects keep declaration order | `pairs` order is undefined |
| Errors | `Error`, V8 stacks, `AggregateError`, `JSON.stringify` labels, `util.inspect` | error tables `{ name, message, traceback, ... }`; `composeError` grafts registration tracebacks best-effort; labels use `%q`; inspection uses `__tostring` | different runtime |

## Fix-type deviations

Confirmed upstream defects fixed in `cordis-lua` (not fixed at the aligned
[`UPSTREAM`](../UPSTREAM) commit). Dedicated tests live in
`test/core/fixes_spec.lua` and `test/core/fidelity_spec.lua`.

| Topic | Upstream defect | Fix |
|---|---|---|
| Effect setup | `fiber.ts:329,355`: the effect wrapper joins the owner's disposables only after `execute` ran, so an unload started from inside `execute` misses the effect | register the wrapper before running `execute`; a synchronous setup failure removes it again |
| Unload guard | `fiber.ts:231-234`: `assertActive` only checks `uid`, so effects created while the fiber is `UNLOADING` escape the `_unload` snapshot (`:492`) and leak | `fiber:assertActive()` still checks `uid`, while `fiber:effect()` also rejects new effects when `state == UNLOADING` (`PENDING` and `LOADING` remain allowed) |
| Plugin publication | `fiber.ts:172,178`: a child fiber publishes `internal/plugin` before it has its `dispose` | assign `dispose` first, then publish |
| Disposal observers | `events.ts:119-124` with `fiber.ts:188`: one throwing `internal/plugin` observer on the dispose path skips the registry removal, unregistration and `_setEpoch` | on the dispose path, every observer runs in isolation; errors are logged |
| Deactivation order | `fiber.ts:398-405`: emits `internal/status` before notifying provision dependents on both activation and deactivation, so a throwing or re-entrant `internal/status` listener on deactivation can prevent dependents from unloading and stall shutdown | on deactivation (`oldState == ACTIVE`), `Fiber:_updateState` calls `notifyProvisions` before emitting `internal/status`, running both under `pcall` (and isolating per-provision notifications) so a failure in one does not skip the other; on activation (`state == ACTIVE`), `internal/status` still runs before `notifyProvisions` |
| Pending fiber cleanup | `fiber.ts:432` with `:188`: a `PENDING` fiber can own effects (`fiber.ctx:effect`, an `internal/plugin` observer), but its epoch is already inactive, so dispose never unloads them | when a disposed fiber has no unload in progress and still holds disposables, unload it explicitly; without effects the status transitions stay upstream's. Test: `test/core/fidelity_spec.lua` |
| In-flight cleanup | `fiber.ts:333-345`: a cleanup started by hand removes the effect from the owner first, so an unload of the owner does not wait for that cleanup | the wrapper stays registered until its asynchronous cleanup settles, and disposing it again returns that cleanup, so the owner's unload joins it. Test: `test/core/fidelity_spec.lua` |
| `internal/update` waterfall guard | `events.ts:70-75`: per-fiber `internal/update` listeners share one `_next` closure over the listener queue, so an earlier listener calling `next()` twice after a later listener vetoes can bypass the veto and reach `restart` | each local `internal/update` listener receives its own single-use `next()` guard matching `waterfall` (`next() called multiple times` on reuse or outer-frame re-invocation). Test: `test/core/fixes_spec.lua` |

Upstream bugs reproduced on purpose (faithful, not deviations): `ctx:mixin(source)`
with a table source reads `ctx["[object Object]"]`, as JS converts the object
to a property key (`reflect.ts:286-289`).

Not adopted: the `effectiveConfig` / `rawConfig` accessors and volatile config.

## Host notes

Properties of the host environment rather than of the port:

- **Without the `debug` library** (sandboxed embedders), Lua runtime tracebacks
  are omitted: `cordis.Error`'s `traceback` and `composeError` degrade to the
  bare message, so Lua call frames have no `file:line`. Host-provided loader
  source locations (`trace.locate`, such as `app.yml:1:3`) and outer stacks
  (`trace.getOuterStack`) are still preserved on loader expression errors (see
  `test/lib/loader_sandbox_spec.lua`). The one core case that checks a Lua
  traceback line, `reflect.spec.ts` "access error", skips itself there
  (`U.requires("debug")`).
- **Without virtual time** (an embedder's real-time scheduler, `test/run.lua --host`),
  the cases written for fake timers are skipped; see [hosts.md](hosts.md).

## Extensions

Generic extension points with no upstream counterpart. They are optional:
a host that omits them sees upstream behavior. Tests: `test/lib/capture_spec.lua` on the
reference host with `contexts = true`; `lua test/run.lua --contexts` runs the
whole suite on such a host.

| Topic | Extension | What it does |
|---|---|---|
| Execution contexts | `host.capture() -> scope` (`scope.run(fn, ...)`, `scope.spawn(fn)`) | User callbacks run in the execution context captured when they were handed to the library ([api-core.md §1](api-core.md#1-host-and-async-primitives)): listeners of `emit` / `bail` / `waterfall` / `serial` run through `scope.run` on the calling task (which can be a drainer for events like `internal/status` or later `serial` steps); `parallel` listeners with a captured scope, components, disposers invoked from a drainer, Future reactions, `cordis.async` / `asyncIter` bodies, and scheduled timer tasks run through `scope.spawn`. Queued components, disposers, and reactions therefore run in their own tasks rather than blocking the drainer. Ordering stays as upstream where upstream relies on microtask order: a provision withdrawn by a sibling disposer waits one host task turn (`future.hop`), so child cleanup that started meanwhile still sees it (`service-dispose.spec.ts:271`). Known timing difference on a capture host: a component's `apply` runs as its own task, so an `await` of a fiber that is still PENDING because its dependency's `apply` has not run yet settles earlier than upstream's microtask order would let it (`fiber.spec.ts:326`, `service-dispose.spec.ts:131`; both pass without `capture`) |
| Root closure | `root:close()` | A terminal close of the root tree. Upstream's root `dispose` is a restart and the root stays usable; `close()` checks `self.fiber.runtime == nil` (so `root:extend():close()` or any derived context sharing the root fiber also closes the root tree), marks the root fiber disposed (later and concurrent registrations on it raise `cannot create effect on inactive context`, cleanup running during the close included), unloads it like any fiber (every effect and child fiber, asynchronous cleanup awaited) and returns a Future that settles when that is done; repeated calls (including re-entrant calls from a synchronous `internal/status` listener during the first close) return the same Future. For embedders that tear down a whole tree (a VM shutting down) |
| Cancellable apply | cancellable apply: `scope.spawn(fn)` may return `{ cancel = fn }` | A fiber disposed while LOADING cancels its component task, if that task has started and is suspended part-way and the host's spawn handle can cancel it. Its Future is rejected with `cordis.future.CANCELLED`, which the reload path treats as the dispose that caused it (not logged, not FAILED), and the unload goes on at once. Upstream lets the `apply` finish and then unloads. A task that has not started yet still runs (`component.spec.ts:175` "root dispose"). Hosts whose spawn returns nothing keep upstream behavior. For embedders whose reloads can be cancelled: a cancelled reload discards the apply it started. Test: `test/lib/capture_spec.lua` "cancels the apply task of a fiber disposed while loading" |
| Provision event | `internal/provide` event | Emits `(ctx, name, value)` before a `provide`, `set`, `accessor`/`mixin`, or pre-provide fiber-less root property write registers or overwrites; a listener's error aborts it unchanged. Upstream has no such event. For embedders that guard provisions. Test: `test/core/provide_event_spec.lua` |
| Introspection and event adapter | `EventsService:resolve`, `:listeners`, `:listenerCount`; read-only `fiber.error`; `fiber:pending()`; `ReflectService:getImpl(name, strict?)` | Public inspection and custom-bus adapter APIs replacing underscore-private accesses: `events:resolve` resolves filtered hooks as an independent copy and emits `internal/dispatch`; `events:listeners` / `:listenerCount` inspect registered listeners (with zero allocation for counts); `fiber.error` exposes the failure value read-only; `fiber:pending()` lists unfulfilled inject names in declaration order; `reflect:getImpl(name, strict?)` returns the isolation-scoped `impl` record for occupancy and provider-ownership checks. Test: `test/lib/introspection_spec.lua` |

## Performance

Shorter execution paths that keep service and lifecycle semantics intact; where
an optimization changes object identity on repeated reads, the table records
the observable difference.

| Topic | Where | What |
|---|---|---|
| Reflect read | `reflect.lua` `handler.get` (`reflect.ts` handler.get) | Mixin accessors registered through `ReflectService:mixin` never use the access-error placeholder and are invoked directly (`getter(ctx, ctx[S.receiver])`) without `pcall` or allocating an error placeholder; user-defined accessors are still called through `pcall(def.get, ...)` without building a closure. A service read skips the `internal/get` waterfall while no listener is registered on `internal/get` and resolves via `locateValues` directly without allocating a `pcall`/fallback closure, result table, or error placeholder: internal events are never dispatched to `internal/dispatch`, so the result is the same. Measured on 150k reads (`ctx.emit`, `ctx.waterfall`, an injected service): about 2% faster; most of the per-read cost is the proxy path itself. Tests: `test/core/fidelity_spec.lua` "reflect read fast path" |
| Mixin bound-method cache | `reflect.ts` `mixin`: every read of a mixed-in method returns a freshly bound function | `ReflectService:mixin` reuses the bound method wrapper per `(service, propKey)` (weak-keyed by `service`) when there is no overriding `receiver` and the live method read from `service` is unchanged (`rawequal`). Observable difference: repeated reads of the same mixin method on the same context (such as `ctx.on` or `ctx.emit`) return the same function object until the service or method is replaced (upstream: a new function on every read). Tests: `test/core/perf_spec.lua` "allocation and hot-path invariants" |
| Injection index | `reflect.ts` `notify(names)`: walks every fiber of every runtime and checks `fiber.inject` for each name | an index of which fibers inject which name (`cordis/inject_index.lua`, kept where `fiber.inject` is set, in the constructor and `_replace`, and dropped when the fiber is removed). With no names `notify` returns at once; when no fiber injects any of the names the walk is skipped; otherwise the walk runs in upstream order and checks only the fibers that inject one of them. What each fiber gets (`_checkImpl`, `_refresh`) and the `internal/service` events are unchanged. In an 82-fiber application tree, every provision entering or leaving ACTIVE walked all 82 fibers; the startup sampling profile had `notify` under at least 16% of the samples. Tests: `test/core/perf_spec.lua` "reflect notify" |
| Traceable cache | `trace.ts` `createTraceable`: a new `Proxy` on every read of a traced value | one traceable per (value, reading context, tracker), cached with weak keys; the proxy holds nothing else, so a cached one behaves the same. Observable difference: two reads of `ctx.svc` from the same context return the same object (upstream: two proxies). Tests: `test/core/perf_spec.lua` "traceable cache" |
| Shadow cache | `trace.ts` `createTraceable` handler: a getter read, a write, a method read and a call each build a new shadow (`useSite.extend({ [symbols.shadow]: defSite })` plus a property proxy), a method read also a new method proxy, and every string read looks up `useSite.reflect.props[associate + '.' + prop]` through the context | per traceable, the shadow of each receiver and the shadow method of each (receiver, name) are reused while the method value and the def site they carry (the value of `tracker.property`) are unchanged; the use site's `reflect.props` table (one table for the life of the reflect service) is read once. Observable difference: two reads of the same method give the same function, and the shadow context a method sees is the same object across calls (it only carries the def site; writes to a context go through its own checks). `svc:inc()` 16.0 µs -> 3.1 µs, a method read 5.8 µs -> 0.8 µs (plain Lua 5.5). Tests: `test/core/perf_spec.lua` "traced method shadow cache"; the caller and shadow semantics stay pinned by `test/core/shadow_spec.lua` |
| Property lookup | hot paths of property access (`proto.get`, `isSpecialProperty`) | `proto.get` walks the plain prototype chain in a loop instead of a call per level (the same lookups in the same order, through the object's current own map); `isSpecialProperty` decides on the first byte without building a substring and converts only a property that can start a number. Property access returns the same values as before; only the call stack seen by `debug.traceback` inside a lookup has fewer frames. Loader bench 48 entries 10.75 → 10.53 ms, a service read through ctx 4.0 → 3.9 µs (plain Lua 5.5, back to back with the parent commit). Tests: `test/core/perf_spec.lua` "hot paths" |
| Resolution cache | `reflect.ts` handler.get: every service read through a context walks the context chain (`has`), builds the access error, runs the read in a closure under `pcall`, and `locate`s the provision through the fibers | the provision a read resolved to is remembered per reader context (weak keys) and property, in an entry that holds nothing strongly (weak values), with a resolution epoch (`cordis/resolve_epoch.lua`); it is reused while the epoch is unchanged, the provision is still there, the read reaches the same context object, and no `internal/get` listener exists. The value is read from the provision on every read (a `nil` or `false` value included) and the traceable made per read (the traceable cache gives the same proxy), so a reader that stays registered keeps nothing of a provision that went away. Every input of the resolution bumps the epoch where it changes: every `proto` write to an existing object (`set`, `defineOwn`, `delete`, `setPrototypeOf`), the fiber fields `locate` reads where `fiber.lua` assigns them (`_replace`, `_reload`, unload), and a fiber's `provisions` where `reflect.lua` adds or deletes one. Only the plain lookup is remembered, never an `internal/get` listener's answer, and a read during which anything changed is not remembered; accessors and fiber-less (root) reads never are. Observable difference: none. A service read through ctx 3.9 µs -> 0.52 µs, 0.35 µs with the trace fast paths (plain Lua 5.5, best of 9 × 200k, back to back against the uncached path). Tests: `test/core/perf_spec.lua` "context read cache"; the `internal/get` rule also by `test/core/fidelity_spec.lua` "reflect read fast path" |
| Trace fast paths | `trace.ts` getTraceable, the traceable handler's method read, `proto` property dispatch | the same lookups with fewer calls: `getTraceable` reads a plain table's or a class instance's own `shadow` / `tracker` in place (identifying class instances by `class._classes[mt]`, which excludes `OBJ`, symbols, and `cordis.null` without comparing against `cordis.null`, so a class's custom `__eq` metamethod is no longer triggered on `getTraceable`; a class instance's inherited tracker is still read through its class chain); `getDataValue` reads a plain table's or class instance's own field in place, then its class chain through the lookup it shares with the general path; traceable and `withProps`/`withProp` proxies share module-level handler tables via `proto._proxyWithContext` with lazily created weak caches plus direct `selfMethods`/`selfShadow` caches when the receiver is the traceable proxy itself; a method that is a Lua function goes straight to its cached shadow method, whose def site is read raw when it is an own field; the associated key of the last property read is kept (the props table is still read live); `TRACEABLE_HANDLER.get` checks plain tables' and class instances' `[S.tracker]` directly without calling `isObject`/`proto.get`; `buildOuterStack()` reuses a shared empty-stack function when the `debug` library is absent; plain `proto` objects use inline single-key storage (`k1`/`v1`, promoting to flat `kv` + ordered `own` `Map` on the second key), direct `pstate` prototype links, and an epoch-guarded ancestor-proxy shortcut for string reads when intermediate plain prototypes carry no string own keys, while proxies use a dedicated `PROXY_OBJ` metatable (`__name = "cordis.Object"`); getter/setter-free classes use table `__index = cls` and omit `__newindex` until a getter or setter is assigned to the class chain; `reflect.handler.get` reads `target`'s own fields and `Context.prototype` methods directly without per-context cache allocation, skips recursive re-entry for `S.receiver`/`S.shadow`, and caches bound mixin methods on root/plain-chain class targets in `resolved[ctx]` (keyed by `resolveEpoch.n` with in-place entry reuse); `EventsService:on` skips `internal/listener` bail when only the built-in listener is installed for non-`internal/update` events, and `emit`/`bail` use zero-pack fast paths with `thisArg` when no `internal/dispatch` hook exists; `Future` job queues store `(fn, argc, a, b)` in flat slots without per-reaction wrapper closures and guard `getmetatable` checks with `type(x) == "table"`; `Fiber:getEffects()` walks `_disposables` linked lists directly. Observable differences: a class with a custom `__eq` metamethod is not invoked by `getTraceable`, traceable/wrapper proxies share their internal handler table and use a distinct proxy metatable with `__name = "cordis.Object"`, `getmetatable(cls.__get)`/`getmetatable(cls.__set)` are non-nil on classes, and `buildOuterStack()` returns the same function object when `debug` is absent. Tests: `test/core/perf_spec.lua` "trace fast paths", "allocation and hot-path invariants", "cordis hot-path storage and dispatch invariants" |

| Proxy hotpath | `proto.lua`, `reflect.lua`, `trace.lua`, `class.lua`, `events.lua`, `registry.lua` | `proto.lua` scopes `strSkipEpoch` invalidation to `underProxy` prototype chains and tracks a single allowed string key (`strOwnOnly`, e.g. `"fiber"`) so `fiber.ctx` chains still jump directly to their ancestor proxy on every other string read, adds a watched-key bitmask (`_watchKey` / `_getWatched`) for O(1) negative checks of `S.shadow`/`S.receiver`/`S.filter` that only shortcuts proxies explicitly marked `passthroughWatched` (`reflect._createRootProxy`, preserving `get` traps on custom proxies such as `withProp`/`withProps`), maintains `_ctxVersion` across all `underProxy` string writes/deletes (including leaf contexts) and watched-key mutations, and caches static handler traps on `_proxyWithContext`; `Context.new` uses a specialized per-root proxy handler (`reflect._createRootProxy`) with direct `tkv`/`tpkv` reads, inline traceable cache hits, and root-target mixin caching (`kind = 4`) validated by `mixinEpoch + ctxVersion` (surviving unrelated `resolveEpoch` bumps); `TRACEABLE_HANDLER.get` checks `selfMethods` cache-first (including `Service` subclasses) with live target/class/def-site validation; getter-free subclasses in `class.lua` use table `__index = cls` chained through `setmetatable(cls, { __index = parent })` and lazily upgrade descendants when a getter is added; built-in `EventsService`, `ReflectService`, and `RegistryService` methods unwrap their own traceable proxy once at entry while preserving `useSite` `ctx` and custom subclasses. Observable differences: none. Tests: `test/core/perf_spec.lua` "cordis hot-path storage and dispatch invariants" |

## timer (`packages/timer`, 1.1.5)

The timer port applies the language-level deviations to this package and
requires the host primitives described below.

| Topic | Upstream | Lua | Basis |
|---|---|---|---|
| Timer primitives and deadlines | `setTimeout` / `setInterval`; `performance.now()` | Built on `host.spawn` + `host.sleep(ms, latch)` + `host.now()`. `TimerService` raises at construction when the host lacks `sleep` or `now`. A delay below 1 ms (0, negative, NaN) clamps to 1 ms (matching Node); a deadline already reached still yields one turn (`sleep(0)`), preventing zero or overrunning intervals from spinning. Deadlines are computed from `host.now()` at registration so late-starting tasks do not shift due times, and intervals skip missed ticks. Throttling reads monotonic `host.now()` only, never `os.time` or `os.clock`. | asynchronous work |
| Cancellation and latch | `clearTimeout` / `clearInterval` | Clearing sets a cancel flag and opens the timer's `latch`. On a host whose `sleep` accepts `latch`, the sleeping task wakes at once; on one that ignores `latch`, the task exits when the old deadline expires. | asynchronous work |
| Execution contexts and errors | Uncaught timer exceptions bubble to the runtime | `throttle` and `debounce` capture the callback's creation context. `timeout`, `interval`, and `debounce` run in tasks spawned in their captured scope; for a trailing `throttle`, the timer task is scheduled in the triggering call's scope and runs the callback inside it via `scope.run` in the creation scope. Errors raised synchronously during scheduled timer callback invocation log through `ctx.logger("timer")` (rejected Futures returned by an async callback are not logged). `throttle`'s leading call runs synchronously via `scope.run`, so an error propagates directly to the caller instead of logging to `ctx.logger("timer")`. | asynchronous work, extensions |
| Timeout | `timeout(delay)` returns a Promise; `promise.finally(dispose)` | returns a Future; `:finally(dispose)` | asynchronous work |
| Async interval | `interval(delay)` returns an `AsyncIterableIterator` (`next` / `return` / `throw`) consumed with `for await` | returns a table with `next`, `return` and `throw` methods returning Futures of `{ done = ..., value = ... }`. `return` is a Lua keyword, so it is called as `iter["return"](iter, v)`; no alias. Lua has no `for await`: the consumer loops on `iter:next():await()` and calls `return` itself when it leaves early | asynchronous work, generators |
| Callback overloads | overloads tell a callback apart with `typeof args[0] === 'function'` | the first argument is a callback unless it is a number, so callable tables (e.g. spies) are accepted | proxies |
| Disposable callbacks | `throttle` / `debounce` return a function carrying `.dispose` | a callable table with a `dispose` closure field: `throttled()`, `throttled.dispose()`; `type(throttled)` is `"table"` | proxies |
| Timer mixins | `ctx.timeout(...)` etc. through the mixin | `ctx:timeout(...)` | method receivers |

## loader (`packages/loader`, 1.0.0-rc.10)

Entry expressions use Lua instead of JavaScript. The remaining differences
apply the language-level deviations to the loader and fix an upstream defect.

Not ported:

- `src/resolve.ts`: writes `.cordis/.gitignore` and `.cordis/resolve.mjs` into
  the project so Node resolves bare specifiers from the config's project. Lua
  modules are found through `require` and `package.path`; the problem does not
  exist.
- `src/internal.ts` `getInternalLoader()` (Node's internal ESM loader).
  `loader.internal` is nil by default and kept as a host-replaceable import
  hook.
- `Loader.envData` from `process.env.CORDIS_SHARED` (JSON handed over by cli /
  hmr across restarts; neither is ported). `envData` is
  `{ startTime = (os and os.time and os.time() * 1000) or (ctx.host.now and ctx.host.now()) or 0 }`.
- the `@cordisjs/fs` base URL, relative specifiers (`./x`) and Windows drive
  letters, together with `resolve.ts`.

| Topic | Upstream | Lua | Why |
|---|---|---|---|
| Expressions | expressions in entry options are `{ __jsExpr: '<JS expression>' }`; `isJsExpr` / `JsExpr`; `evaluate(ctx, expr)` runs `with (ctx) { return eval(expr) }` | `{ __luaExpr = "<Lua expression>" }`; `isLuaExpr` / `LuaExpr`. `evaluate(ctx, expr)` is `load("return " .. expr, "=<cordis:expression#N>", "t", env)()`, first result. `env.__index(k)` reads `ctx[k]` when `Context.has(ctx, k)` and `_G[k]` otherwise (`__newindex` alike), which is how `with (ctx)` resolves names; a name bound in neither raises `ReferenceError` (`<name> is not defined`), as an unbound identifier does in JS, so a misspelled flag in `disabled` disables the entry instead of reading as nil; reading an undeclared service fails through the context proxy as upstream. Only expressions compile; `!x`, `a && b`, `x++` are written `not x`, `a and b` and function calls. Truthiness is Lua's: `0` and `""` are true. `interpolate` also descends into the own fields of a table with an ordinary metatable (defaults through `__index`, class instances), copying it with the same metatable only when something was evaluated; a table whose metatable is protected (`__metatable`) cannot be copied with it and is kept as an opaque value. Expressions are trusted code: whatever the host exposes in `_G` (`os`, `io`, `require`, `load`, ...) is reachable from them | user decision |
| Error locations | `traceEvaluation` parses V8 frames and maps frames inside the expression (found by `sourceURL`) to source locations; `SourceLocation.column` counts UTF-16 units | `xpcall` + `debug.traceback`; frames inside the expression are found by the chunk name `<cordis:expression#N>`. Lua reports lines only, so the column is the start of that line; columns count bytes. String errors are wrapped into error tables before the traceback is grafted, so `evaluate` may raise a different value than the expression did | errors; Lua frames carry no column |
| Module imports | `EntryTree.import(name, getOuterStack)` goes through Node's loader / `import()`; `ERR_MODULE_NOT_FOUND` for `name` itself becomes `ModuleNotFoundError` (first line + Node's hints), a failing nested import passes through; `unwrapExports` handles `default` / `__esModule` | returns a Future. Calls `loader.internal:import(name)` when the host set one, else `require(name)`. When the `require` error's first line is `module '<name>' not found:` for the requested name, it raises `ModuleNotFoundError` (`message` = that line without the colon, then the searcher lines as hints; `specifier = name`; `code = "ERR_MODULE_NOT_FOUND"`; traceback = `getOuterStack()` frames); a missing module required from inside the component passes through. `unwrapExports(x)` returns `x.default` when `x` is a non-class table with a non-nil `default` field, and otherwise returns `x` itself (so a `cordis.class` table is preserved even if it has a `default` field); no `__esModule` | Lua's module system is `require` |
| Prototype chains | prototype chains: `Object.create(ctx[Context.isolate])`, `Object.setPrototypeOf(entry.ctx, parent.ctx)` (an entry's context is re-parented when it moves), `Object.setPrototypeOf(this._intercept, ...)`, `for...in`, `Object.hasOwn`, `Reflect.ownKeys` | `cordis.proto`: `create`, `setPrototypeOf` (re-parents derived contexts and plain proto objects; asserts on root `Context` proxies and rejects prototype cycles), `keys` (for...in order), `hasOwn`, `ownKeys`, `delete`. `swap(target, source)` deletes the own keys of `target` and copies the own keys of `source`. Entry options and update patches may be plain tables or JS-like objects; they are merged, copied and compared by their own keys | proxies, ordering |
| Symbols | `Symbol.for('cordis.entry')`, `Symbol.for('cordis.group')`, `accessGlobal()`'s `Symbol.for('cordis.isolate.<key>@<label>')`; `LocalRealm`'s `Symbol('<key>#<id>')`; the `Symbol('anonymous')` key in `EntryGroup.update` | `cordis.symbolFor(key)` / `cordis.symbol(desc)`. `Group[EntryGroup.key] = true` is a static on the class table | symbols |
| Null values | `null` vs `undefined`: `Entry.merge` deletes keys whose value is nullish, so `update(id, { disabled: null })` removes the field; `EntryTree.update(id, options, parent)` reads `parent === undefined` as "do not move" and `null` as "move to the root group"; `fiber.uid === null` | removing a field and moving to the root group use `cordis.null`: `{ disabled = cordis.null }`, `tree:update(id, opts, cordis.null)`; a nil `parent` means "do not move". An `inject` value that evaluates to nil is stored as `cordis.null`, so the dependency stays (without config) instead of the key disappearing. `uid` is nil | null values |
| Sequences | arrays: `group.data`, `splice(position ?? Infinity, 0, ...)`, `indexOf`; `create(options, parent, position = Infinity)` counts from 0; issue paths such as `inject.0` count from 0; `Array.isArray` | sequences count from 1: `position` counts from 1 and defaults to appending; issue paths count from 1 (`inject.1 must be a string`). An *array* is a table whose keys are exactly `1..#t`, each present (`#` may report any border of a table with holes, so the keys are counted); a *plain object* is a table that is not an array and not an expression; **an empty table is both**, so `intercept = {}` and `config = {}` are valid | Lua has no array type |
| Key ordering | `sortKeys(options)` reorders keys (id, name, the rest alphabetically, config) for stable write-back | not done: Lua tables have no key order, `deepEqual` does not depend on it, and the loader writes no files (`Loader:commit` is a no-op) | ordering |
| Async loader | `async` methods, `Promise.all(ids.map(async ...))`, `Promise.allSettled`; the deferred notification at the end of `init()`; `Group`'s `async *[Service.init]` and the outer component's `async *apply` | Futures; concurrency through `cordis.async` + `Future.all` / `allSettled`; the deferred notification is a host task; the two async generators are `cordis.asyncIter`. JS key order in `EntryGroup.update` (integer-like ids first) is not reproduced: old ids in insertion order, then new ones. It only affects which concurrent task starts first. Where upstream relies on microtask order, the order is made explicit: the part of an `async` method before its first `await` runs in the caller (e.g. `Entry:update` assigns the options and `Entry:init` sets `_initTask` before returning); a `Group` shares its entry list as `data` from construction, so entries inserted before its `init` has run are kept (upstream starts from `[]`); `EntryTree:await()` yields once before checking the tasks, as an `async` function settles no earlier than the next job | asynchronous work, generators, ordering |
| Errors | `EntryValidationError extends TypeError`, `ModuleNotFoundError extends Error`, `instanceof`, `error.stack`, `relocate()` rewriting `stack` | error tables with `name`, `message`, `issues` (or `specifier`, `code`) and `traceback`; `EntryValidationError.is(x)`, `ModuleNotFoundError.is(x)`; `relocate` rewrites `message` and `traceback` | classes, errors |
| Accessors | getters `entry.id`, `entry.disabled`, `entry.context`, `tree.context`; arrow fields `trace`, `getOuterStack` | getters stay property reads through the class `__get`; methods are colon calls; arrow fields are closure fields, dot-called | method receivers, classes |
| Identifiers | ids from `Math.random().toString(16).slice(2, 10)` | `string.format("%08x", math.random(0, 0xffffffff))`, checked for collisions as upstream | different runtime |

| Topic | Upstream | Port | Why |
|---|---|---|---|
| Entry settlement | `entry.ts` `init()`: after each entry's fibers settle, `if (this.loader.getTasks().length) return; this.ctx.reflect.notify(['loader'])`, a walk over every entry per entry, so starting n entries is O(n²) | per loader, a count of the entries still settling; only the entry that brings it to zero walks `getTasks()` and notifies. A consumer injecting `loader` with `await: true` still starts only once every entry has settled. `notify(['loader'])` fires once per wave instead of up to once per entry | 48 entries took 29 ms, now 16.5 ms (plain Lua 5.5, coroutine host); `test/loader/settle_spec.lua` |
| Isolation notifications | `isolate.ts` step 6: `ctx.reflect.notify(keys, ...)` for both sides of every isolation patch, also when no name moved (`keys` empty); a notify walks every fiber of every runtime | step 6 is skipped when no name moved; with no names a notify updates no fiber | in an 82-fiber application tree, every loader entry made two full walks for nothing; 48 entries 16.5 ms -> 12.3 ms (plain Lua 5.5); `test/loader/settle_spec.lua` |
| Empty entry inject/intercept | `entry.ts` `_resolveInject` / `_applyIntercept`: resolves and deep-compares `inject` and interpolates/swaps `intercept` even when both options and current maps are empty | fast-paths nil/empty `options.inject` and `options.intercept` when `self.inject` / `self._intercept` are already empty plain objects | avoids per-entry `pcall`, `proto.create`, `deepEqual`, and `swap` allocations when rows carry no row-level `inject`/`intercept`; `test/core/perf_spec.lua` |

Cross-tree moves, rc.12 compatibility, and the fix for stale isolation bindings
(#329) are already upstream. Requiring an explicit update for a failed fiber
after its inputs or dependencies are corrected matches upstream behavior. Not
adopted from downstream forks or proposals: ids containing `:` (upstream
rejects them on purpose), volatile config, config accessors, module identity
for hot reload, timer locale metadata, and making `update` wait for a disabled
entry's disposal (progress remains visible through `tree:await()`, so this is a
contract difference rather than a defect).

## Unported upstream packages

At the aligned [`UPSTREAM`](../UPSTREAM) commit, `cordis-lua` ports the three runtime packages `core`, `timer`, and `loader` (upstream `packages/group` only re-exports `Group` from `loader`, which `cordis.loader` already exports). The remaining Node/CLI/web peripheral packages in upstream `packages/` are out of scope and not ported:

| Upstream package(s) | Upstream role | Why not ported |
|---|---|---|
| `cli`, `cli-cordis` | Standalone Node CLI entrypoint and worker runner | `cordis-lua` is an embedded Lua library; hosts supply their own process/CLI entrypoint |
| `create` | Project scaffolding CLI (`create-cordis`) | Node/npm project generator; not applicable to Lua embedders |
| `env` | Process environment / `.env` integration | Host/embedder specific; no portable Lua stdlib equivalent |
| `hmr` | File-watching hot module reload over Node ESM | Tied to Node's module graph and filesystem watcher; embedders manage reloads via `registry:replace` / `loader` |
| `include` | Config file inclusion (`yaml`/`json` loader plugin) | Depends on Node filesystem/loader ecosystem; embedders load configuration directly |
| `package-manager` | npm/yarn/pnpm package management service | Node package manager wrapper; not applicable to Lua |
| `logger-console` | Terminal ANSI console logger target | Embedders supply their own `ctx.logger:exporter` |
| `fs` | Filesystem abstraction (`@cordisjs/fs`) | Lua has no standard async filesystem layer; embedders provide host I/O |
| `http`, `http-socks` | HTTP/HTTPS and SOCKS client services | Network I/O is host-provided; pure Lua 5.5 has no built-in HTTP stack |
| `server` | HTTP server service | Network server I/O is host-provided |
